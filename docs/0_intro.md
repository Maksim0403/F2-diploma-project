# Науковий апарат проєкту

### Актуальність теми

Сучасні мобільні застосунки для догляду за домашніми тваринами переважно реалізовано за моделлю CRUD із перезаписом поточного стану сутності (остання вага, дата останнього щеплення). Така модель незворотно знищує хронологію змін, унеможливлює темпоральні запити, ретроспективний аудит та верифікацію коректності послідовності медичних процедур. Додатковою інженерною проблемою є обробка потоку геопозицій у реальному часі: необроблені GPS-вимірювання містять шум, що за простого порогового порівняння спричиняє хибні спрацювання детекції виходу із зони, а зростання кількості клієнтів потребує горизонтального масштабування ingestion-контуру та обмеження затримки (latency) між подією та сповіщенням.

Застосування Event Sourcing у поєднанні з асинхронною взаємодією сервісів через Apache Kafka забезпечує незмінний журнал подій, відновлення стану на довільний момент часу та слабку зв'язність bounded contexts (Pet Health, Geo, Notification). Відмовостійкість (fault tolerance) досягається семантикою at-least-once доставки з ідемпотентною обробкою споживачів, що виключає втрату та дублювання побічних ефектів за умов збоїв і повторної доставки повідомлень. Використання Redis для кешування проєкцій і зберігання проміжного стану фільтрації геоданих знижує навантаження на PostgreSQL та зменшує затримку читання, а контейнеризація (Docker) і CI/CD-конвеєр (GitHub Actions) забезпечують відтворюваність розгортання та автоматизований контроль якості. Безпека реалізується автентифікацією на основі JWT та авторизацією на рівні ресурсу, що запобігає доступу до даних чужих тварин. Отже, розроблення системи на основі зазначених архітектурних рішень є актуальною інженерною задачею.

### Об'єкт дослідження

Процес реєстрації, зберігання та обробки хронологічно впорядкованих подій життєдіяльності домашньої тварини (медичних подій, змін фізичних показників, геопросторових вимірювань) у розподіленій системі з гарантіями цілісності, відтворюваності історії та своєчасності сповіщення.

### Предмет дослідження

Методи та архітектурні патерни побудови подієво-орієнтованої розподіленої системи: Event Sourcing із проєкціями та компенсуючими подіями, декомпозиція за bounded contexts, асинхронний обмін повідомленнями через Apache Kafka з ідемпотентною обробкою, патерн Specification для валідації доменних медичних правил, алгоритми фільтрації геопросторового шуму (hysteresis, N послідовних точок), а також технології їх реалізації: Python, FastAPI, Pydantic, SQLAlchemy, PostgreSQL, Redis, Alembic, Docker, GitHub Actions, Firebase Cloud Messaging.

### Мета роботи

Розроблення подієво-орієнтованого мобільного застосунку для догляду за домашніми тваринами, що реалізує методи Event Sourcing, патерн Specification та асинхронну взаємодію сервісів через Apache Kafka, з метою підвищення відтворюваності історії даних, коректності медичних процедур, достовірності геозонування та відмовостійкості доставки сповіщень у процесі обробки подій життєдіяльності тварини.

### Завдання проєкту

1. Проаналізувати існуючі програмні рішення для догляду за домашніми тваринами та підходи до реалізації Event Sourcing, виконати порівняльний аналіз за критеріями збереження історії, валідації медичних правил, моніторингу геопозиції та надійності доставки, оформивши огляд відповідно до ДСТУ 8302:2015.
2. Обґрунтувати вибір технологічного стеку (Python, FastAPI, PostgreSQL, Redis, Apache Kafka, Kotlin, Jetpack Compose) за критеріями продуктивності, масштабованості, відмовостійкості та підтримуваності.
3. Спроєктувати архітектуру системи із застосуванням нотацій UML та C4: діаграми контекстів, контейнерів і компонентів, схему потоків подій між сервісами Pet Health, Geo, Notification та API Gateway, модель подій і проєкцій.
4. Розробити та формалізувати алгоритми критичних вузлів: побудови стану з потоку подій, валідації правил вакцинації (Specification), фільтрації GPS-шуму з детекцією виходу із зони, ідемпотентної обробки повідомлень Kafka.
5. Спроєктувати інтерфейс мобільного клієнта та схему розгортання системи (Docker Compose, CI/CD-конвеєр), реалізувати програмні компоненти відповідно до спроєктованої архітектури.
6. Виконати інструментальний аудит якості програмного коду та надійності системи: модульне й інтеграційне тестування, оцінювання покриття коду, статичний аналіз, перевірка поведінки за умов збоїв і повторної доставки повідомлень, вимірювання затримки обробки геопозицій.
7. Провести науково-практичну апробацію результатів роботи та підготувати наукову публікацію (тези або статтю) за матеріалами дослідження.
