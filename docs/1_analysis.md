Аналіз 11pets, PetDesk і Tractive GPS засвідчив наявність трьох функціонально відмінних підходів до розв’язання задач догляду за домашніми тваринами. 11pets призначено для ведення медичної історії тварин і планування процедур, PetDesk забезпечує взаємодію власників тварин із ветеринарними інформаційними системами, а Tractive GPS спеціалізується на відстеженні геопозицій і контролі безпечних зон. Водночас доступні публічні матеріали не дають змоги повністю встановити внутрішні протоколи обміну даними, типи сховищ і кількісні межі масштабування всіх трьох платформ. Тому порівняння ґрунтується на підтверджених функціональних характеристиках і доступних архітектурних відомостях без визначення технічної переваги окремого продукту за відсутності достатніх доказів.

У межах кваліфікаційного проєкту передбачено застосування Event Sourcing для збереження незмінної історії медичних подій, PostgreSQL — для їх персистентного зберігання, FastAPI — для реалізації HTTP API, а Apache Kafka — для асинхронної взаємодії між bounded contexts Pet Health, Geo і Notification. Така архітектура має забезпечити відновлення стану тварини на визначений момент часу, відокремлення логіки обробки медичних даних від обробки геопозицій і зменшення залежності основних операцій від доступності сервісу сповіщень. Redis передбачено використовувати для операцій, що потребують швидкого доступу до тимчасових даних, без заміни ним основного журналу подій.

Обрані архітектурні рішення мають низку технічних компромісів. Застосування Event Sourcing потребує підтримки проєкцій стану, контролю узгодженості та механізмів повторної обробки подій. Використання Apache Kafka збільшує складність розгортання, конфігурації та моніторингу системи. Асинхронна взаємодія між компонентами допускає тимчасову неузгодженість похідних представлень даних. Для зменшення відповідних ризиків передбачено реалізацію ідемпотентної обробки повідомлень, контроль повторних спроб, перевірку доменних правил і тестування механізмів геозонування на послідовностях координат із похибками.

Остаточна оцінка ефективності запропонованої архітектури потребуватиме експериментальної перевірки, зокрема тестування коректності обробки подій, поведінки системи за умов часткової відмови компонентів і навантажувальних характеристик. Результати аналізу формують основу для подальшого проєктування компонентів системи, моделі даних і механізмів взаємодії, які розглядаються в наступному розділі.
