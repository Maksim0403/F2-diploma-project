# Thesis Proposal

## 1. Попередня робоча назва проєкту

**UA:** Розроблення мобільного застосунку для догляду за домашніми тваринами на основі подієво-орієнтованої архітектури (Event Sourcing)

**EN:** Development of a Mobile Pet Care Application Based on Event-Driven Architecture (Event Sourcing)

### 2. Актуальність і проблема

Наявні застосунки для власників домашніх тварин зберігають лише поточний стан профілю: останню вагу, дату останнього щеплення, дату останнього візиту. Історія змін втрачається або фрагментується, тому неможливо простежити динаміку здоров'я тварини та виявити відхилення. Такі рішення також не перевіряють логічну коректність послідовності медичних процедур і не забезпечують контроль місцезнаходження тварини в реальному часі.

**Інженерні проблеми, які розв'язує проєкт:**

- **Втрата історії даних.** Класична модель «перезапис поточного стану» знищує хронологію. Потрібна незмінна історія подій із можливістю відновити стан на довільну дату.
- **Відсутність валідації медичної логіки.** Застосунки не перевіряють коректність послідовності процедур (інтервали між дозами, порядок вакцинації, вікові обмеження).
- **Немає моніторингу безпеки в реальному часі.** Обробка потоку геопозицій потребує фільтрації GPS-шуму та швидкої детекції виходу із зони без хибних спрацювань.
- **Надійність доставки.** Сповіщення про щеплення й порушення зони критичні за часом, тому система має гарантувати відсутність втрати подій за умов збоїв і повторної доставки повідомлень.

### 3. Сформована ідея продукту

**Тип системи:** мобільний застосунок (Android, Kotlin) із серверною частиною на основі подієво-орієнтованої архітектури: Event Sourcing, три сервіси за bounded contexts (Pet Health, Geo, Notification) та API Gateway. Сервіси взаємодіють асинхронно через Apache Kafka. Система розгортається в контейнерах із повним CI/CD-конвеєром.

**Суть ідеї:** застосунок для власників домашніх тварин, який ведення профілю, нагадування про щеплення, годування та догляд реалізує не як просту форму даних, а як систему з трьома властивостями:

- хронологічна історія подій;
- автоматична перевірка медичних правил;
- обробка геопросторових даних у реальному часі.

### 4. Детальний опис функціоналу (Core Features)

1. **Профілі власника та тварин.** Реєстрація, автентифікація (JWT), підтримка кількох тварин на одного власника, авторизація на рівні ресурсу.
2. **Журнал медичних подій (Event Sourcing).** Щеплення, візити, зміни ваги, симптоми зберігаються як незмінні події. Поточний стан профілю будується проєкцією; помилкові записи виправляються компенсуючими подіями.
3. **Календар щеплень із Rule Engine.** Перевірка доменних правил: мінімальні інтервали, порядок доз, вікові обмеження. Правила реалізовані за патерном Specification і покриті тестами.
4. **Темпоральні запити та історія візитів.** Перегляд стану тварини на довільний момент часу та історії візитів до ветеринара.
5. **Геозонування.** Задання безпечної зони, приймання потоку геопозицій, фільтрація шуму (hysteresis, N послідовних точок), детекція виходу за межі зони.
6. **Нагадування та push-сповіщення.** Планувальник нагадувань про годування, догляд і щеплення; сповіщення про порушення зони через Firebase Cloud Messaging.

### 5. Попередній інструментарій та технологічний стек

**Мови програмування:**

- Мобільний клієнт: Kotlin
- Бекенд: Java або Python (остаточний вибір уточнюється)

**Архітектурні патерни:**

- Event Sourcing
- Мікросервісна архітектура

**Фреймворки:**

- Мобільний клієнт: Jetpack Compose, Room
- Бекенд: Spring Boot, Spring Security, Spring Data JPA, MapStruct (Java) / FastAPI, Pydantic, SQLAlchemy (Python)

**Бази даних і брокери:**

- PostgreSQL
- Redis
- Apache Kafka

### DevOps-інструменти

- Docker, Docker Compose
- GitHub Actions
- Firebase Cloud Messaging
- Liquibase (Java) / Alembic (Python)
